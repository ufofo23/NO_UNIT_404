# 아트 발주서

이 문서 하나만 들고 가면 출시에 필요한 아트를 전부 만들 수 있게 쓴 것이다. 각 항목은
**어디에 쓰이는지 · 정확한 규격 · 파일을 어디에 두면 코드가 알아서 집어가는지**를 같이
적는다. 규격이 틀리면 스토어 업로드나 파트너 사이트에서 거부당하고, 그때는 이미 심의와
Steam Direct 대기가 끝난 뒤라 그대로 출시가 밀린다.

체크: `Tools ▸ NO404 ▸ Release ▸ Release Readiness Report` 가 2절·3절의 개수를 센다.

---

## 0. 톤 — 아트 이전에 합의할 것

GDD 4.4가 제작 원칙으로 못박은 두 줄이 아트에도 그대로 적용된다.

> 시신과 화상 묘사는 직접 노출보다 실루엣, 소리, 기록으로 전달한다.
> 정신질환을 공포의 원인으로 사용하지 않는다.

그리고 등급(`RATING_GRAC.md` 4절)이 **15세 이용가**를 전제로 잡혀 있다. 유혈·고어·신체
훼손이 캡슐 아트나 스크린샷에 한 장이라도 들어가면 등급 근거가 무너지고 심의를 다시
받아야 한다. **아트는 등급 신청 자료의 일부다.**

키 비주얼의 중심은 괴물이 아니라 **없는 문**이다. 403과 405 사이의, 도면에 없는 벽.

## 1. 월드 · 캐릭터 (게임 내)

현재 전부 프리미티브다. 교체는 **재배치가 아니라 스왑**이 되도록 설계되어 있다.

- 모든 치수는 `Assets/_Project/Scripts/Gameplay/BuildingSpec.cs`에서 나온다.
- `BuildingSpecTests`가 치수 드리프트를 빌드 실패로 만든다. 즉 **아래 표를 지키면
  게임플레이 코드를 한 줄도 안 건드리고 교체된다.**

| 요소 | 치수 | 비고 |
|---|---|---|

| 벽 높이 | 2.6m | |
| 세대 현관문 | 0.9 × 2.05m | |
| 방화문 | 1.0 × 2.1m | |
| 계단 1단 폭 | 1.25m | |
| 평면 그리드 | 0.5m | 모든 모듈이 이 배수여야 한다 |
| 관리실 | 8 × 6m | |
| 주차장 섹션 | 25 × 18m | 기둥 6, 차량 6 + 미등록 차량 1 |
| 기록실 | 6 × 5m | 선반 4, 서버랙 1 |
| 404호 | 18m² (4.5 × 4m) | |
| 엘리베이터 카 | 1.5 × 1.5m, 천장 2.4m | |

**단 하나의 예외 — 이것은 버그가 아니다.** 4층 403과 405 사이 벽만 다른 층보다 1.2m
넓고 0.5m 그리드에서 벗어나 있다. 그 방이 거기 지어졌다는 뜻이므로 **그리드에 맞추지
말 것.** (`BuildingSpec.HiddenWallExtra`)

### 1.1 지하 고정물 — 순찰 경로가 걸려 있다

`Assets/_Project/Scripts/Gameplay/BasementLayout.cs`가 주차장 기둥·차량과 기록실
선반·서버의 좌표를 갖고 있고, **5일차 순찰 경로가 그 사이를 지나간다.**
`PatrolRouteTests`가 모든 구간을 이 테이블에 대조한다.

기둥이나 차를 옮기고 싶으면 `BasementLayout`을 고치면 된다 — 월드와 순찰이 같이 따라오고,
경로가 물체를 통과하게 되면 테스트가 먼저 깨진다. **모델만 바꾸고 좌표를 그대로 두면
아무것도 안 깨진다.**

### 1.2 등장인물 9명

전원 일상복, 신체 강조 없음(심의 3.1). 목록과 성격은 GDD 5장.

### 1.3 CCTV 10–12번 카메라

현재 주차장·옥상 그레이박스에 임시로 놓여 있다. 원래 자리는 **아카이브 복도**와
**재활용장**이며, 그 두 공간은 아트 패스에서 만든다.

## 2. 도전과제 아이콘 — 24종 × 2 = **48장**

Steamworks 파트너 사이트에 과제당 **해제/미해제 2장**을 올린다.

| 항목 | 값 |
|---|---|
| 크기 | **64 × 64 px** |
| 포맷 | PNG (알파 가능) |
| 장수 | 48 |
| 프로젝트 내 위치 | `Assets/_Project/Art/Achievements/` |
| 파일명 | `ACH_FIRST_SHIFT_unlocked.png` / `ACH_FIRST_SHIFT_locked.png` |

미해제 아이콘 관례: 같은 그림의 실루엣 또는 탈채도 버전.

**숨김(●) 과제는 아이콘도 스포일러가 되면 안 된다.** 파트너 사이트에서 Hidden으로
체크해도 해제 순간 그림이 보인다.

API Name 24개 전체 목록과 조건, 숨김 여부는 `STEAM.md` 2.2절에 있다. 게임 코드의 진실은
`Assets/_Project/Scripts/Core/GameIds.cs`의 `AchievementIds.All`이며, 철자가 한 글자라도
다르면 그 과제는 영원히 해제되지 않는다.

## 3. 스토어 페이지 아트

### 3.1 캡슐 6종 (필수)

Steam이 크기를 강제한다. 하나라도 빠지면 스토어 페이지를 게시할 수 없다.
위치: `Assets/_Project/Art/Store/`

| 이름 | 크기 | 쓰이는 곳 |
|---|---|---|
| Header capsule | 460 × 215 | 상점 상단, 위시리스트 목록 |
| Small capsule | 231 × 87 | 검색 결과 — **제목이 읽혀야 한다** |
| Main capsule | 616 × 353 | 프론트페이지 특집 |
| Vertical capsule | 374 × 448 | 특집 세로 배너 |
| Library capsule | 600 × 900 | 구매자 라이브러리 |
| Library hero | 3840 × 1240 | 라이브러리 상단 배경 |

주의 두 가지:

- **Small capsule에서 제목이 안 읽히면 검색 결과에서 사라진 것과 같다.** 231 × 87에
  한글 "404호는 없습니다"가 들어가는지 실제 축소해서 확인할 것.
- **Library hero에는 로고를 넣지 않는다.** Steam이 그 위에 별도 로고를 얹는다.

### 3.2 스크린샷 최소 5장 (1920 × 1080)

**그레이박스 스크린샷은 절대 올리지 않는다.** 환불 사유가 되고 리뷰에 그대로 남는다.

GDD 2.3의 8개 훅 중 시각적으로 성립하는 것부터 고른다. 권장 5장:

1. 관리실 PC — CCTV 2×3 그리드에 이상현상이 하나 떠 있는 순간
2. 인터폰 화면 — 방문자 얼굴과 판별 근거 두 개가 같이 보이는 구도
3. 증거 보드 — 연결선이 여러 개 그어진 상태
4. 4층 복도 — 403과 405 사이의 그 벽
5. 5일차 정전 — 손전등 하나로 지하 주차장

### 3.3 트레일러

GDD 2.3의 8개 훅. 60~90초. **첫 10초 안에 "없는 호실"이 나와야 한다.**

오디오가 아직 합성음이고 음악(GDD 19.4)이 0개이므로 **트레일러는 오디오 패스 뒤에
만든다.** 순서를 바꾸면 두 번 만들게 된다.

#### 이 게임은 비명으로 팔 수 없다 — 그건 설계다

호러 게임 마케팅의 기본값은 스트리머가 의자에서 튀어오르는 클립이다. **이 게임에서는
그 클립이 안 나온다.** 우연이 아니라 설계다:

- 가장 큰 소리도 환경음 대비 **+8dB를 못 넘고**, `AudioService`와 `AudioPolicyTests`가
  코드 수준에서 강제한다 (GDD 19.3)
- 쫓기는 구간은 **전체 게임에 두 번**뿐이다 (GDD 15.2)
- 초자연 존재는 플레이어를 이유 없이 공격하지 않는다 (GDD 4.4)

이 제약은 등급 근거이기도 하다 — `RATING_GRAC.md` 3.3이 "점프 스케어를 코드 수준에서
제한한다"를 15세 이용가의 핵심 논거로 쓴다. **제약은 그대로 두고, 파는 방법을 바꾼다.**

**팔아야 할 것은 공포가 아니라 섬뜩함이다.** 놀라는 얼굴이 아니라 **알아차리는 얼굴**을
노린다. 이 게임의 클립은 "악!"이 아니라 "어? 잠깐만"이다.

| 쓰지 말 것 | 대신 쓸 것 |
|---|---|
| 갑자기 튀어나오는 얼굴 | 관리 PC 세대 수가 **92에서 93으로** 바뀌었다가 돌아오는 2초 |
| 비명·굉음 | 403과 405 사이 벽이 다른 층보다 **넓다**는 것을 재는 장면 |
| 추격 | 인터폰 화면과 주민 DB가 **서로 다른 이름**을 띄운 정지 화면 |
| 피·시신 | 폐기를 고른 직후의 한 줄 — `같은 목소리를 다시 들을 방법은 없다` |

컷 구성 원칙:

1. **정보를 보여준다.** 이 게임의 공포는 화면이 아니라 기록에서 온다. 데이터베이스 한
   줄, 출입 기록 두 줄의 시각 차이, 도면에 없는 방 — 전부 읽히는 것이어야 한다
2. **컷을 길게 간다.** 4초 미만이면 이상현상을 못 읽는다. GDD 12.4가 게임 안에서 최소
   4초를 보장하는 것과 같은 이유다
3. **정적을 남긴다.** 음악이 빠지는 구간이 이 게임의 무기다
4. **마지막 카드는 제목이 아니라 문장으로.** `404호는 없습니다` 자체가 훅이다

#### 스트리머 축

이 게임이 방송에서 사는 방식은 놀람이 아니라 **시청자 참여**다. 판별 게임은 채팅이
"들여보내지 마!"를 외치게 만든다. 문 앞 응대를 밤당 6~9회로 올린 것도(GDD 13.4) 이
때문이다. 스트리머 대상 문구는 이 축으로 쓴다:

> 채팅이 틀리면, 그 사람은 건물 안에 남는다.

### 3.4 등급 표시 이미지

GRAC 등급이 확정된 뒤 받는다. 스토어 페이지와 게임 내 양쪽에 표기 의무가 있는지는
`RATING_GRAC.md` 5절의 확인 목록에 있다.

## 4. 게임 내 UI 아트

현재 `Assets/_Project/Scripts/UI/UiFactory.cs`가 코드로 그리는 레거시 uGUI이고, 폰트만
실물(Pretendard, SIL OFL 1.1)이다.

교체 방식: **각 View는 그리지 않고 `UiFactory`만 호출한다.** 즉 `UiFactory`의 위젯을
TMP + 스프라이트로 바꾸면 화면 전부가 따라온다. View 파일은 건드리지 않는다.

지켜야 할 것:

- **모든 문구는 `Resources/NO404/strings.csv`에서 `Loc.T(key)`로 온다.** 아트 작업 중
  문자열을 이미지에 굽지 말 것 — 영어판이 깨진다.
- 자막 규격 GDD 16.17: 하단 중앙 2줄, 한국어 28자 / 영어 52자, 크기 90~160% 조절.
- 색맹 모드에서 증거 연결선은 **색 + 굵기 + 관계 문구** 세 가지로 구분된다. 색만으로
  구분되는 UI를 새로 만들면 접근성 테스트가 깨진다.
- 압박 표시는 숫자로 보여주지 않는다(GDD 16.19). 예비 전력 게이지만 예외다.

## 6. 오디오 — 아트가 아니지만 같은 패스에서 끝내야 한다

"아트만 하면 끝"이라고 볼 때 가장 자주 빠지는 항목이라 여기 적는다.

| 항목 | 현재 | 필요 |
|---|---|---|
| 효과음 19종 | `Tools/GenerateAudio.py` **합성음** | 실물 녹음으로 교체 |
| 음악 (GDD 19.4) | **0개** | 신규 제작 |
| 보이스 (GDD 19.5) | **0개** | 신규 제작 또는 자막 전용으로 범위 축소 결정 |

교체 방법: `Resources/NO404/Audio/`의 같은 이름 위에 덮어쓰면 코드 변경이 없다.

**라우드니스 정책은 코드가 강제한다.** GDD 19.3에 따라 가장 큰 소리도 일반 환경음 대비
**+8dB를 넘지 못하며**, `AudioService`의 믹스 정책과 `AudioPolicyTests`가 이를 검증한다.
이 규칙은 심의 자료(3.3절)에서 "점프 스케어를 코드 수준에서 제한한다"는 근거로 제출된다.
**정책을 넘는 소리를 넣으면 테스트가 깨지고 등급 근거도 같이 깨진다.**
