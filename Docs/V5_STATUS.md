- 손실은 **반드시 이유 키를 동반**한다. v5.0 6.1/7.1이 "예측 가능했던 위험에서만

  정상업무 2연속(+2, 야간 최대 +4) · 야간 종료(+5/+8, SAN +7/+10)

  `SUNJA_CARE`를 bool 3개로 쪼개면 "돌봤고 동시에 거절했다"가 저장 가능해진다

**스탯 스케일 변경** — v5.0 5.2에 맞춰 `ArchiveIntegrity` · `ChairmanAlert` ·
`HarinResonance`를 0~10 → 0~100으로 옮겼다. 이 값을 읽는 임계값과 증감을 **같은
변경 안에서 전부 ×10** 했다(감시/압수 임계, 하린 공명, 교통 밀도, 초상화 임계,
증거 획득). 세이브 마이그레이션도 ×10 하되 `ArchiveIntegrity`만 새 시작값 50을
바닥으로 얹는다 — 6일 내내 기록을 지킨 세이브에 "보존된 기록 0"을 돌려주는 쪽이
더 나쁜 거짓말이다.

## 3. 안 된 것 / 알려진 한계

### 3.1 가장 큰 공백 — 랜덤 후보 84개

v5.0 4.1은 밤당 15개(메인 1 + 후보 14)를 요구한다. **현재 밤당 1개다.**

여기서 파생되는 결과:

- 페이싱이 얇다. "밤이 흘러가는 느낌"이 없다
- **실질 도달 엔딩이 A 하나뿐**이다. B/C/D는 산술적으로 도달 가능하고 테스트로
  확인했지만, 현재 콘텐츠에는 거기까지 깎을 위험이 없다
- 방문자 분배 약속("마지막 작업이 열릴 때 문 앞에 한 명")이 충족 불가능하다.
  케이스가 하나면 산술적으로 전원이 거기 몰린다 (`CallerDistributionTests`에 조건부로 표시됨)

### 3.2 HP/SAN 회복 수단이 월드에 없다

`VitalService`에 구급함(4회, +18)과 Grounding(야간 2회, +8) 로직이 있지만
**월드에 누를 물건이 없다.** 현재 회복은 야간 종료 보너스뿐이다.
엔딩이 HP/SAN으로 결정되는 이상 이건 실질적인 구멍이다.

### 3.3 미구현 (v5.0 기준)

- **§9 프롤로그** (12~18분 튜토리얼) — 없음

  Grounding 35초 보호 구간, 90초 무입력 시 유도. 전부 미구현
- **§4.4-3 Fallback Variant** — 조건 미달 퀘스트를 대체 변형으로 전환하는 단계.
  변형 시스템 자체가 없어서 현재는 그냥 뽑히지 않는다 (`NightPoolService`에 `ASSUMPTION:` 표시)

## 5. 이번 작업에서 배운 것 (재발 방지)

테스트가 잡았고 컴파일·플레이로는 잡히지 않았던 것들:

- **N2-M01을 인터폰 트리거로 작성** → 야간 체인이 그 밤의 척추를 못 봄. 페이싱·방문자·
  마지막 작업이 전부 사라졌다. → `EveryFixedMainIsOnTheTimetable`로 고정
- **N4 전화 두 통이 한 케이스에 몰림** → `Impossible` 우선순위가 회장 전화를 밀어냄.
  케이스 훅을 떼는 것은 설계 규칙 위반이었고, 올바른 해법은 `releaseDelaySeconds`였다
- **인트로가 레거시 `UnityEngine.Input`** → 이 프로젝트는 Input System 전용이라
  매 프레임 예외. 첫 줄에서 멈추고 어떤 키도 안 먹혔다. **빌드로 나갔다**
- **문자열을 기존 키에 중복 추가** + 값 안의 쉼표 미인용 → 로드 순서로 우연히 동작
- **캠페인 테스트가 마지막 밤만 확인** → Night 1 메인이 한 번도 실행되지 않는데 통과
- **엔딩을 글자로만 단언** → 결과 절반이 적용되지 않아도 통과

교훈 두 가지:

- **컴파일과 부팅 로그로는 부족하다.** UI를 새로 만들면 그 화면을 실제로 도는
  PlayMode 테스트를 같이 붙인다
- **관례를 확인하고 나서 이유를 붙인다.** 레거시 `Input` 건은 프로젝트 전체에서
  그것만 예외였는데, 주석에 "의도적으로 관례를 벗어난다"고 써 두기까지 했다
